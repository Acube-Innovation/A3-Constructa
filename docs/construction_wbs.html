Construction WBS

From quotation to report: one breakdown for the whole project lifecycle
Masiha Services SARL  •  ERPNext v15 + A3 Constructa  •  Planning document  •  September 2026

The client's Design & Build requirement (BOQ → WBS → Item mapping) covers the budget side of a project. This document extends the same breakdown to everything that happens around it: how a job is quoted and won, how it is billed, how the work is planned and carried out with people and equipment, how materials are bought, and how all of it is reported back against the WBS.

It is a planning document, not a description of the system as built. Every element is still mapped to what A3 Constructa and ERPNext have today, so it can be merged into the app phase by phase (section 8).

1. How to read this document

RuleMeaning
Numbering 1.0 Area → 1.1 Package → 1.1.1 Work item → 1.1.1.1 Activity. On a live project the Operations branch (3.2) is repeated per project and carries the project code as a prefix, e.g. PRJ-001.3.2.3.2-A = project 001, Architectural, Flooring, WBS A.
Two kinds of breakdown Process WBS (areas 1, 2, 4, 5): the business steps every project goes through, used to organise the system and its documents. Project (product) WBS (area 3.2): the physical work of one project — Cost Head → Work Package → WBS → resource lines — which is the key every cost, bill and task is tagged with.
100% rule A parent holds exactly the sum of its children plus an unallocated balance. Levels are never added together in a report: Architectural = Flooring + Doors & Windows + Painting + unallocated.
WBS vs cost code The WBS says where / what part of the work (WBS A: ground-floor porcelain). The cost code says what kind of cost (material, labour, equipment, subcontract, overhead). Every transaction line carries both, as the client flow requires: Project + WBS + Cost Code + Item + Quantity.
Lowest level = work package A WBS stops where one responsible person can plan, buy for and measure it. Below that, work is broken into schedule activities and tasks (3.3), not into further WBS levels.
EXISTS
A custom A3 Constructa doctype, field or report already covers it.		 STANDARD
ERPNext / HRMS covers it out of the box; set up and use.		 CONFIG
Needs configuration: workflow, custom field, dimension, print format.		 CUSTOM
Needs new development: a doctype, controller logic or a report.

Industry practice — estimating and CRM
  • RIB CostX / iTWO, Candy, Sage Estimating: take-off is linked to the drawing, and every BOQ rate is a build-up of resources. A change to a resource price flows through every rate that uses it.
  • Procore, Buildertrend, CMiC: the estimate becomes the original budget when the job is won, with no re-keying. The bid pipeline (bid board) shows bids by stage, value and win rate.
  • Oracle Aconex / Procore Bid Management: tender documents, addenda and bidder queries are controlled and dated so every price can be tied to the document revision it was based on.
  • Adopt: resource-based rate build-up (1.5.1), quotation revisions with reasons (1.6.2), and a one-click handover from the won quote to Sales Order + Project + budget BOQ (1.8).

Industry practice — progress billing
  • Procore (Prime Contract & Owner Invoices), Viewpoint Vista, CMiC, Sage 300 CRE: billing is done on a schedule of values, the contract BOQ, line by line: work completed previously + this period + stored materials, less retention (the AIA G702/G703 layout in the US; FIDIC IPCs elsewhere).
  • Procore Change Events → Change Orders: potential changes are logged the day they arise, then priced, approved and pushed to both the contract (revenue) and the budget (cost) at once.
  • SAP PS: WBS elements are flagged as billing elements; billing plans are milestone-based or resource-related (cost-plus). Revenue is posted to the WBS so margin is visible per WBS.
  • Adopt: a client IPC doctype that works like our supplier-side Work Certificate, a Change Event → Variation Order flow that updates contract and budget together, and WBS on every revenue line.

Industry practice — planning, labour and equipment
  • Oracle Primavera P6: EPS → project → WBS → activities. Activities are resource-loaded (labour, equipment, material) with FS / SS / FF / SF logic and lags. Baselines are kept as copies, and the critical path and float are calculated from the logic.
  • Procore / InEight / HCSS HeavyJob: foremen record crew hours, equipment hours and quantities per cost code each day on a phone (timecards + daily log). Productivity = installed quantity ÷ man-hours, against the estimate.
  • Viewpoint Vista, CMiC, Sage 300 CRE: equipment is a cost centre of its own. Usage hours × internal rate are charged to the job cost code, and the equipment ledger recovers its owning and operating cost.
  • Last Planner / lean: master schedule → 3-week look-ahead with constraint removal → weekly work plan, measured by percent plan complete.
  • Adopt: WBS on Task with resource lines, a daily site report that captures labour, equipment and quantity by WBS in one form, and an internal-rate equipment log.

Industry practice — procurement against the WBS
  • SAP PS / S/4HANA: every requisition and PO line is account-assigned to a WBS element. Availability control checks budget − commitments − actuals when the document is saved, and warns or blocks at set tolerances.
  • Procore Commitments, Oracle Unifier, CMiC: POs and subcontracts are commitments on the budget line. The cost report shows original budget, approved changes, revised budget, committed, invoiced and to-complete in one row per cost code.
  • Distribution lines: ERP systems (SAP, Oracle, D365) split one PO line across several account assignments by quantity or %. The equivalent here is one PO line per WBS for the same item.
  • Adopt: requests generated from WBS Allocation, a budget check on Material Request / PO, and WBS as an accounting dimension so invoices post to it (closes gap-analysis items T1–T5).

Industry practice — reporting
  • Procore Budget view, Oracle Unifier cost sheet, CMiC job cost: one row per cost code with fixed columns: original budget, approved changes, revised budget, committed, pending changes, actual, cost to complete, projected cost, over / under.
  • Primavera P6 / SAP PS / Oracle Primavera Cloud: earned value per WBS (PV, EV, AC, SPI, CPI, EAC) and S-curves against the baseline, following ANSI/EIA-748 and PMI practice.
  • Contractor accounting (Viewpoint, Sage 300 CRE, Foundation): monthly WIP schedule of over / under billing per job, which drives revenue recognition under IFRS 15 (percentage of completion).
  • Adopt: a single job cost report with those columns, drill-down through the WBS tree, and EVM once task progress is recorded (closes gap-analysis items R1–R5).
